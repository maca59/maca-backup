Support — maca BackUp

Här får du hjälp med maca BackUp — backup och återställning för WordPress. Snabbast får du svar via supportformuläret i pluginet (maca BackUp → Support). Du behöver inte logga in på maca.se.

Kontakt

E-post: support@maca.se
Ange gärna webbplats-URL, pluginversion (maca BackUp → Support eller under Tillägg), WordPress-/PHP-version och en kort beskrivning. Feltext från fliken Logs eller förloppspanelen hjälper. Skärmdumpar är välkomna.

Svarstid: vardagar, vanligtvis inom 1–2 arbetsdagar.

Innan du skriver till oss

  1. Kontrollera att maca BackUp är uppdaterat till senaste version.
  2. Acceptera villkor och integritetspolicy under maca BackUp → Support (backup/restore är pausade tills båda är godkända).
  3. Titta i Logs och i förloppspanelen efter felmeddelanden.
  4. Beskriv vad du försökte: full / databas / filer / incremental / differential, restore, Smart Restore eller lagringstjänst.
  5. Klistra inte in hemliga nycklar, lösenord eller API-tokens i supportärenden om det går att undvika.

Krav & installation

Vilka krav gäller?

WordPress 6.0 eller nyare och PHP 8.2 eller nyare. Filbackup och import kräver PHP-utökningen ZipArchive. FTP kräver FTP-utökningen; SFTP kräver ssh2.

Behöver jag en licensnyckel?

Nej. maca BackUp är GPL-licensierat och har ingen betald licensaktivering. Installera pluginet, aktivera det och godkänn villkoren under Support.

Var hittar jag pluginet i admin?

Toppmenyn maca BackUp. Flikar: Dashboard, Backups, Restore, Smart Restore, Schedule, Storage, Logs, Settings, Support.

Backup

Vilka backuptyper finns?

På Dashboard: Create full backup, Incremental, Differential, Database only och Files only. Jobbet körs i bakgrunden — du kan lämna sidan.

Incremental / differential fungerar inte

De kräver först en färdig full backup. Skapa en full backup och försök igen.

Backupen stannar, timeoutar eller “hänger”

  • Minska belastningen under Settings: Files per chunk, Tables per chunk och eventuellt ZIP split size.
  • Exkludera tunga mappar under Exclude paths (en sökväg per rad, relativ till webbplatsroten).
  • Kontrollera att PHP har tillräckligt med minne och att WP-Cron fungerar (särskilt vid schemalagda jobb).
  • Jobb utan progress i cirka 2 timmar markeras som misslyckade — se Logs.

Pre-update backup

Under Settings → Pre-update backups kan du ta backup innan WordPress-, plugin- eller temauppdateringar. Högst en pre-update-backup per timme, så massuppdateringar inte startar ett nytt jobb för varje paket.

Återställning

Hur återställer jag?

Fliken Restore: välj backup (eller importera .zip / .enc), välj omfattning (hela webbplatsen, databas, wp-content, uploads, plugins, themes eller anpassad sökväg) och kör Restore now. Använd Test restore / Preview changes först för att verifiera arkivet utan att ändra livesajten.

Vad är Smart Restore?

Under Smart Restore jämför du livesajten med en backup och återställer bara nya, ändrade eller markerade filer (Compare → välj → Restore selected).

Import misslyckas

Filen måste vara en giltig maca-backup (.zip eller krypterad .enc) med manifest.json. Storleken får inte överstiga webbplatsens maxuppladdning (wp_max_upload_size). För stora filer: ladda upp via FTP/SFTP till servern och importera därifrån om din miljö tillåter det, eller kontakta hostingleverantören om uppladdningsgränsen.

Lagring (Storage)

Vilka destinationer stöds?

Local storage, FTP, SFTP, Google Drive, Dropbox, OneDrive samt Amazon S3 / Backblaze B2 / S3-kompatibelt. Konfigurera under Storage och välj aktiv leverantör.

“(not configured)” eller uppladdning misslyckas

  • Kontrollera att rätt leverantör är vald och att uppgifter är sparade.
  • FTP/SFTP: värd, port, användare, lösenord/nyckel och sökväg. SFTP kräver ssh2 på servern.
  • Moln: förnya OAuth-token (Google Drive / OneDrive) eller kontrollera API-nycklar (Dropbox / S3).
  • Skicka aldrig hemliga nycklar i klartext till support om det går att undvika — beskriv felet och felkoden i stället.

Schema, kryptering & notifieringar

Schemalagda backups körs inte

Scheman beror på WP-Cron. Kontrollera att webbplatsen får trafik (eller att systemcron anropar wp-cron.php), att schemat är aktiverat under Schedule, och att tider visas i webbplatsens tidszon. Anpassad cron uttrycks i UTC.

Krypterade backups går inte att öppna

Aktivera Encrypt backup archives (AES-256-GCM) och sätt samma Backup passphrase under Settings som när backupen skapades. Utan rätt lösenfras går krypterade arkiv inte att återställa.

E-postnotifieringar

Under Settings kan du slå på e-post vid lyckad/misslyckad backup och restore. Om mail inte kommer fram beror det oftast på webbplatsens e-postleverans — testa med ett SMTP-plugin eller hostingleverantörens mail.

maca Hub

Valfritt heartbeat till maca Hub för övervakning av flera webbplatser. Aktiveras under Settings → maca Hub. Det skickar statusuppgifter (t.ex. webbplats-URL och version), inte innehållet i dina backups. Backups lagras alltid hos dig (lokal disk eller din molnlagring) — maca hostar inte arkiven.
